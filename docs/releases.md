# 发行与更新

平台标签为 `v0.1.0-preview.N`，HyperFrames 标签为 `hyperframes-v0.1.0-preview.N`。发行资产一旦发布不覆盖；修复重新增加预览序号。

平台安装器及 ZIP 是未签名 Windows x64 测试包。工具包独立发布，平台初次安装不下载工具。源代码许可证为 MIT；组件运行环境使用各自许可。

## 发布者流程

1. 在 Windows CI 编译命名管道辅助程序，运行原生进程、协议与权限验收。
2. 固定锁文件构建平台，运行安装包内容检查，确认未携带四套工具。
3. 用固定源码构建 FFmpeg，保存二进制及完整对应源码。构建 HyperFrames 独立包，生成逐文件清单及许可。
4. 运行功能、真实取消、异常恢复、界面及旧工具干净 VM 安装验收。
5. 发布不可变的平台与工具预发行资产，附 SHA256、源代码、许可和验收记录。
6. 用发布者私钥签名工具目录。私钥不在仓库、组件、CI 日志和发行资产中；程序只携带公钥。
7. 在独立 checkout 更新 `distribution/catalog/catalog.signed.json` 和 `distribution/updates/preview.yml`。工具目录与平台更新源分别修改，不能用 GitHub 最新任意 Release 作为平台版本来源。
8. 使用隔离配置实际下载并安装下一个平台版本，重开旧数据；通过真实签名目录升级组件并重开旧工程。验证成功后补齐公开验收记录。

`scripts/prepare-distribution.cjs` 根据已发布资产生成两个分离的目录。它不推送，也不创建或覆盖发行资产。工具签名使用本地 `MEDIAHUB_SIGNING_KEY` 指定的密钥，默认私钥位于已忽略的 `.publisher` 目录。

## 使用者更新

平台启动只检查更新。用户选择下载后校验并暂存，选择安装后才执行安装器。升级日志记录来源版本、目标版本和新版本就绪回执；异常退出不自动重新安装。

HyperFrames 更新通过已签名工具目录按需进行。运行任务或打开 Studio 时先结束使用，再更新组件。健康检查失败恢复旧版本。删除工具保留共享工作空间。
